# Лабораторна робота №13. Робота з результатами запиту до БД, як з об’єктами

## Тема та мета роботи

Тема ЛР №13 за уточненням до робочої програми — **«Робота з результатами запиту до БД, як з об'єктами»**. Пов’язана тема розділу [робочої програми](../../+РПНД%20WП%202023+.docx) — «Класи та екземпляри класів».

Мета — навчитися отримувати результати SQL-запитів до MariaDB як об’єкти PHP, читати їхні властивості та викликати простий метод власного класу. Продовжити роботу з предметною областю попередніх лабораторних.

## Передумови та середовище

Повторіть створення таблиць і запити з [ЛР №11](../lab-11/README.md) та підключення PDO з [ЛР №12](../lab-12/README.md).

Використовуйте **PHP 8.1**, розширення `pdo_mysql`, **MariaDB 11.x**, phpMyAdmin, редактор коду та браузер. Основне середовище — **OSPanel 6+**, альтернатива — **XAMPP із PHP 8.1** та сервером MariaDB 11.x. Налаштування наведено в [пам’ятці середовища](../../ENVIRONMENT.md). Laravel у цій роботі не використовується.

## Теоретичні відомості

**Клас** описує властивості та методи майбутніх об’єктів. **Екземпляр класу**, або об’єкт, створюється оператором `new`. Властивості зберігають стан об’єкта, методи виконують дії. Усередині методу `$this` позначає поточний об’єкт, а оператор `->` дає доступ до його властивостей і методів.

```php
<?php
class Product
{
    public $name;

    public function __construct($name)
    {
        $this->name = $name;
    }

    public function getLabel()
    {
        return 'Товар: ' . $this->name;
    }
}

$first = new Product('Хліб');
$second = new Product('Молоко');
$first->name = 'Житній хліб';
echo $second->getLabel(); // Товар: Молоко
```

`__construct()` автоматично викликається під час створення об’єкта та задає його початковий стан. Обидва об’єкти мають однаковий набір методів, але власні значення властивості `name`. Зміна `$first->name` не змінює `$second->name`.

`public` дозволяє звертатися до властивостей і методів ззовні класу. На цьому занятті використовуємо лише відкриті властивості та методи. Інші модифікатори доступу, наслідування та інтерфейси розглядатимемо пізніше. Оголошення типів у власному класі поки опускаємо, щоб зосередитися на будові об’єкта.

PDO може повертати рядки різними способами: `fetch(PDO::FETCH_ASSOC)` дає масив із доступом `$row['name']`, а `fetch(PDO::FETCH_OBJ)` — об’єкт `stdClass` із доступом `$row->name`. Виклик `fetchObject(Product::class)` створює екземпляр власного класу та записує значення колонок у його однойменні властивості. Кожний прочитаний рядок стає окремим об’єктом. Наприкінці результату `fetchObject()` повертає `false`.

У прикладі нижче виконуємо звичайний запит PDO у `index.php`, а кожний рядок отримуємо як об’єкт `Product`. Клас описує лише товар: його властивості й прості дії з ними. Зміна властивості такого об’єкта змінює лише дані в пам’яті поточного PHP-запиту: для зміни запису в MariaDB потрібен окремий UPDATE.

## Завдання

1. Створити навчальну таблицю MariaDB та перевірити її в phpMyAdmin.
2. Виконати коротку вправу з двома об’єктами `Product`.
3. Прочитати результати PDO як об’єкти `stdClass`, а потім як об’єкти власного класу `Product`.
4. Знайти товар за ID, змінити властивість отриманого об’єкта й викликати його метод.
5. Адаптувати приклад до свого варіанта з попередніх ЛР та додати простий метод роботи з властивостями.

## Хід роботи

### 1. Підготуйте базу даних

Запустіть вебсервер і MariaDB у своєму середовищі. Створіть окремий каталог `lab-13`; не очищуйте спільні каталоги. У phpMyAdmin створіть навчальну базу `web_lab13` з кодуванням `utf8mb4`, відкрийте її та виконайте SQL:

```sql
CREATE TABLE products (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    category VARCHAR(50) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

INSERT INTO products (name, category) VALUES
('Хліб', 'Випічка'),
('Молоко', 'Молочні продукти'),
('Булочка', 'Випічка');

SELECT id, name, category FROM products ORDER BY id;
```

Перегляньте структуру та три записи. Через phpMyAdmin змініть назву одного товару й повторіть SELECT. Експортуйте структуру та тестові дані в SQL-файл. Для PHP підготуйте користувача лише з правом SELECT на цю базу; створення таблиці й початкове наповнення виконуйте окремим обліковим записом із відповідними правами.

### 2. Створіть два екземпляри простого класу

Збережіть приклад `Product` у файлі `objects.php`. Запустіть `php objects.php` у консолі свого PHP 8.1. Виведіть назви обох об’єктів до та після зміни `$first->name`. Поясніть, де опис класу, де створення об’єктів, де виклик методу. Після цього переходьте до роботи з БД.

### 3. Налаштуйте PDO

Створіть `connection.php`:

```php
<?php
$dsn = getenv('DB_DSN');
$user = getenv('DB_USER');
$password = getenv('DB_PASSWORD');

if ($dsn === false || $user === false || $password === false) {
    throw new RuntimeException('Налаштуйте змінні підключення до БД.');
}

return new PDO($dsn, $user, $password, [
    PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
    PDO::ATTR_EMULATE_PREPARES => false,
]);
```

Задайте для процесу PHP змінні `DB_DSN`, `DB_USER`, `DB_PASSWORD`. Приклад DSN: `mysql:host=127.0.0.1;port=3306;dbname=web_lab13;charset=utf8mb4`; хост і порт замініть фактичними. Префікс `mysql:` використовує драйвер PDO MySQL для підключення до MariaDB. Пароль беріть із локального середовища та не додавайте до репозиторію чи звіту. PHP самостійно не читає довільний `.env`-файл. Налаштування вебпроцесу та консолі можуть відрізнятися.

### 4. Опишіть клас рядка та отримайте об’єкти з БД

Створіть `Product.php`. Це окремий клас для рядка БД; навчальний `objects.php` запускайте окремо й не підключайте до сторінки каталогу.

```php
<?php
class Product
{
    public $id;
    public $name;
    public $category;

    public function getLabel()
    {
        return $this->name . ' — ' . $this->category;
    }
}
```

Назви властивостей збігаються з колонками SELECT. Конструктор тут не потрібен: PDO заповнить оголошені властивості. Якщо застосовувати `fetchObject()` до класу з конструктором, за замовчуванням PDO спочатку заповнює властивості, а потім викликає конструктор; присвоєння в ньому можуть перезаписати прочитані дані.

Спочатку порівняйте два способи читання одного рядка. Тимчасово виконайте цей фрагмент у PHP-сценарії після підключення PDO:

```php
$statement = $pdo->query('SELECT id, name, category FROM products ORDER BY id');
$plain = $statement->fetch(PDO::FETCH_OBJ);
if ($plain !== false) {
    var_dump($plain);
    echo $plain->name; // Для цього досліду використовуйте консоль.
}

$statement = $pdo->query('SELECT id, name, category FROM products ORDER BY id');
$product = $statement->fetchObject(Product::class);
if ($product !== false) {
    var_dump($product);
    echo $product->getLabel();
}
```

Для запуску цього досліду з консолі додайте на початку окремого тимчасового файлу `<?php`, підключіть `Product.php` та отримайте `$pdo` з `connection.php`. Після досліду не залишайте діагностичний вивід у вебсторінці.

Обидва об’єкти мають властивості з назвами колонок. Об’єкт `stdClass` містить отримані дані; власний клас `Product` також надає написаний нами метод `getLabel()`. Другий SELECT виконуємо повторно, щоб знову прочитати перший рядок: кожний fetch пересуває курсор результату.

Додайте до досліду `$product->name = 'Навчальна назва';` всередині перевірки успішного читання. Повторно викличте `getLabel()`: метод використає нове значення властивості. Перевірте в phpMyAdmin, що запис у БД не змінився.

### 5. Відокремте підготовку даних від HTML

Залиште простий поділ на PHP-сценарій та HTML-шаблон. Запити виконуються безпосередньо в `index.php`; окремий клас для доступу до БД не створюємо. Тут вивчаємо об’єкти товарів та їхні можливості.

| Файл | Що містить |
| --- | --- |
| `connection.php` | Знайоме з попередньої роботи підключення PDO |
| `Product.php` | Властивості товару й метод getLabel() |
| `index.php` | Звичайні запити PDO, читання об’єктів і підключення шаблону |
| `catalog.view.php` | HTML та показ готових об’єктів |

У файлах із чистим PHP не пишіть HTML і не закривайте тег `<?php`. У шаблоні залишайте виведення, прості умови та цикли. SQL виконуйте до підключення шаблону. Функцію `escape()` залишаємо на початку `index.php`, а викликаємо під час виведення тексту в шаблоні.

Збережіть у `index.php`:

```php
<?php
require_once __DIR__ . '/Product.php';

function escape($text)
{
    return htmlspecialchars($text, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
}

$rows = [];
$found = null;
$error = '';
$hasSearch = array_key_exists('id', $_GET);

try {
    $pdo = require __DIR__ . '/connection.php';
    $statement = $pdo->query('SELECT id, name, category FROM products ORDER BY id');
    while (($product = $statement->fetchObject(Product::class)) !== false) {
        $rows[] = $product;
    }

    if ($hasSearch) {
        $id = filter_input(INPUT_GET, 'id', FILTER_VALIDATE_INT, [
            'options' => ['min_range' => 1],
        ]);
        if ($id === false || $id === null) {
            $error = 'Ідентифікатор має бути додатним цілим числом.';
        } else {
            $statement = $pdo->prepare(
                'SELECT id, name, category FROM products WHERE id = :id'
            );
            $statement->bindValue(':id', $id, PDO::PARAM_INT);
            $statement->execute();
            $found = $statement->fetchObject(Product::class);
        }
    }
} catch (Throwable $exception) {
    error_log((string) $exception);
    http_response_code(500);
    $error = 'Каталог недоступний. Перевірте журнал PHP.';
    $rows = [];
}
require __DIR__ . '/catalog.view.php';
```

Створіть `catalog.view.php`. Він отримує вже підготовлені `$rows`, `$found`, `$error` та `$hasSearch` з `index.php`:

```php
<!doctype html>
<html lang="uk">
<head>
    <meta charset="utf-8">
    <title>Каталог товарів</title>
</head>
<body>
<h1>Каталог товарів</h1>
<form method="get">
    <label>ID товару <input type="number" name="id" min="1" required></label>
    <button type="submit">Знайти</button>
</form>
<?php if ($error !== ''): ?>
    <p><?= escape($error) ?></p>
<?php else: ?>
    <ul>
    <?php foreach ($rows as $row): ?>
        <li><?= (int) $row->id ?>:
            <?= escape($row->getLabel()) ?></li>
    <?php endforeach; ?>
    </ul>
    <?php if ($rows === []): ?>
        <p>Каталог порожній.</p>
    <?php endif; ?>
    <?php if ($hasSearch): ?>
        <?php if ($found === false): ?>
            <p>Запис не знайдено.</p>
        <?php else: ?>
            <p><?= escape($found->getLabel()) ?></p>
        <?php endif; ?>
    <?php endif; ?>
<?php endif; ?>
</body>
</html>
```

Відкрийте `http://web-prog.local/lab-13/` для прикладу домену OSPanel або `http://localhost/lab-13/` для типового XAMPP. Використайте фактичний домен і шлях свого проєкту. Додатковий варіант — із каталогу роботи виконати `php -d display_errors=0 -d log_errors=1 -S 127.0.0.1:8080` та відкрити `http://127.0.0.1:8080/`. Для Apache також вимкніть показ діагностики у відповіді та ввімкніть журналювання.

Знайдіть цикл читання об’єктів і виклик `$row->getLabel()` у шаблоні. Масив `$rows` містить окремі товари, а не рядки HTML. `fetchObject()` повертає `false`, коли рядків більше немає; це також результат пошуку за відсутнім ID. Порівняйте список із SELECT у phpMyAdmin. Змініть навчальний запис у phpMyAdmin й оновіть сторінку: PHP має прочитати нові дані з БД.

Валідація перевіряє допустимість ID, параметризація відокремлює значення від SQL, а `htmlspecialchars()` захищає текстовий HTML-вивід від XSS. Ці дії не замінюють одна одну. Сторінка виконує лише читання через GET. Якщо надалі додаєте вебформи зміни даних, використовуйте POST і перевірку CSRF-токена; у цій роботі такі форми не є обов’язковими.

## Перевірка та очікуваний результат

Для обов’язкового прикладу й власного варіанта зафіксуйте очікування та фактичний результат:

| Сценарій | Очікуваний результат |
| --- | --- |
| Відкриття без параметра `id` | Список відповідає таблиці в MariaDB |
| Наявний додатний ID | Знайдено відповідний запис |
| Відсутній додатний ID | Повідомлення «Запис не знайдено» |
| `id=abc`, `id=0`, `id=-1`, `id[]=1` | Повідомлення про некоректний ID, без SQL-помилки |
| Назва `<b>Тест</b>` у тестовому записі | Видно буквальний текст, він не стає HTML-розміткою |
| Зміна запису в phpMyAdmin | Після оновлення сторінки видно нове значення |
| Виклик власного методу для одного з двох об’єктів | Результат відповідає властивостям цього об’єкта; другий об’єкт не змінюється |
| Перевірка першого елемента через `var_dump($rows[0])` за наявності даних | Об’єкт Product із властивостями id, name, category |
| Тимчасова зміна властивості name прочитаного об’єкта | Підпис об’єкта змінюється; SELECT у phpMyAdmin показує попереднє значення |
| Тимчасово неправильний DSN | Загальне повідомлення; деталі лише в журналі PHP |
| Перегляд розподілу коду | У файлах логіки немає HTML; у шаблоні немає SQL, читання запиту чи зміни даних |

Перевірте синтаксис командою `php -l` для кожного створеного PHP-файлу. Перевірте сформований HTML через [W3C Markup Validation Service](https://validator.w3.org/), передаючи HTML-відповідь, а не PHP-код. Відновіть SQL-експорт в окремій тестовій базі та порівняйте записи.

Очікуваний результат — каталог на PHP і MariaDB, у якому результати запитів представлені об’єктами власного простого класу. Студент читає властивості, викликає метод об’єкта та пояснює відмінність між зміною об’єкта в пам’яті й запису в БД.

## Контрольні питання

1. Чим клас відрізняється від його екземпляра?
2. Що роблять `new`, `__construct()`, `$this` та `->` у вашому прикладі?
3. Чому зміна назви першого об’єкта `Product` не змінює другий?
4. Чим властивість відрізняється від локальної змінної методу?
5. Як назви колонок запиту пов’язані з властивостями отриманого об’єкта?
6. Чим відрізняються FETCH_ASSOC, FETCH_OBJ та fetchObject(Product::class)? Який із цих способів дозволяє викликати наш метод getLabel()?
7. Де зберігаються записи після завершення PHP-запиту?
8. Чому перевірка ID, параметризований SQL і екранування HTML потрібні окремо?
9. Які властивості використовує ваш додатковий метод? Що в ньому позначає `$this`?
10. Чи змінює присвоєння `$product->name` запис у MariaDB? Чому?
11. Які дані передає `index.php` шаблону? Чому SQL і валідація мають виконуватися до виведення HTML?
