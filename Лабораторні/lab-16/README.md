# Лабораторна робота №16. Створення класу визначеної моделі ч.1

## Мета роботи

Створити класи-нащадки універсальної моделі та використати успадкований CRUD без копіювання SQL.

## Обладнання

PHP 8.1, PDO MySQL, MariaDB 11.x, OSPanel 6+ або XAMPP із відповідними версіями. Редактор коду та браузер. [Вимоги середовища](../../ENVIRONMENT.md).

## Теоретичні відомості

У [ЛР 14](../lab-14/README.md) ми описували кожну модель повністю. У [ЛР 15](../lab-15/README.md) винесли повторюваний CRUD у `Model`. Проте виклики `Model::find($pdo, $id, 'books')` змушують щоразу пам’ятати назву таблиці, а всі результати мають один клас.

У цій роботі додаємо до `Model` властивість `protected static string $defaultTable = '';`. У конструкторі використовуємо `$this->table = $table ?: static::$defaultTable;`, а аргумент `$table` у конструкторі й статичних методах робимо необов’язковим зі значенням `''`. Решта CRUD і `save()` залишаються з ЛР 15.

```php
class Book extends Model
{
    protected static string $defaultTable = 'books';
}

$books = Book::all($pdo);
$book = Book::find($pdo, 1);
if ($book !== null) {
    $book->title = 'Нова назва';
    $book->save();
}
```

`new static(...)` у базовому класі повертає саме `Book`, коли метод викликано через `Book::`. `User` аналогічно задає таблицю `users`. SQL не копіюємо в нащадки. `all()`, `find()`, `create()` — статичні; `update()`, `save()`, `delete()` — методи екземпляра. `find()` повертає `null`, якщо запису немає. Зв’язки між сутностями додамо в ЛР 17.

Зберігаємо структуру ЛР 15: `app/core`, `app/config`, `app/views`, `public/index.php`; додаємо `app/models`. Усі підключення виконує `public/index.php`, спочатку базовий клас, потім нащадки. Контролерів і автозавантаження поки немає. Значення SQL передаємо параметрами PDO, HTML екрануємо через `e()`. Дані перевіряємо до запису; назви таблиць задаємо в коді. При додаванні форм використовуємо POST та CSRF-токен. Приклад користувачів демонструє перегляд, а не реєстрацію: універсальний `create()` сам не хешує пароль.

## Хід роботи
1. Запустіть PHP 8.1 і MariaDB 11.x у своєму середовищі.
2. Створіть окремий проєкт `lab-16`, не очищуючи спільні каталоги. Створіть базу `lab16`, виконайте [schema.sql](src/schema.sql) і налаштуйте PDO. Корінь вебсервера — `src/public`.
3. Порівняйте виклики універсального Model із ЛР 15 з викликами класів-нащадків.
4.  Розгляньте приклад за посиланням, поданим нижче.
5.  Зробіть рефакторінг коду минулого проекту:
    1.  Використовуючи приклад розділіть папку проекту на окремі підпапки
    2.  Доопрацюйте клас `Model`
    3.  Для дочірніх класів на кожну сутність створіть окремі файли, наприклад `User.php`, `Book.php`, `Car.php`, тощо та розмістіть їх у директорії `models`
    4.  Перевірте коректність роботи проекту після рефакторінгу
    5. Перевірте CRUD, збереження нового й наявного об’єкта через save() та правильний клас результатів.
6.  Для проекту створіть папку "lab 16" в своєму репозиторії "web-progr" на Github. Завантажте кінцеві файли лабораторної роботи. 
7.  Для кожного етапу роботи зробіть знімки екрану та додайте їх у звіт з описом кожного скіншота
8.  Додайте програмний код завдання для самомтійного виконання
9.  Дайте відповіді на контрольні запитання
10. Додайте в кінці звіту посилання на репозиторій та папку з лабораторною роботою
11. Збережіть звіт у форматі PDF
12. Додайте звіт до репозиторія
