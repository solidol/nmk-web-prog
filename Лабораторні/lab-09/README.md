# Лабораторна робота №9. Обробка графіки. Бібліотека GD

[Перелік усіх робіт](../README.md)

## Мета роботи

Навчитися створювати растрові зображення засобами GD у PHP, будувати діаграми з даних, додавати текстовий водяний знак та повертати зображення у HTTP-відповіді. Порівняти растрову PNG-діаграму з векторною SVG-версією.

## Обладнання

Основне навчальне середовище — **OSPanel 6+ з PHP 8.1**. Альтернатива — **XAMPP із PHP 8.1**. Налаштування домену, каталогів і консолі наведено в [пам’ятці середовища](../../ENVIRONMENT.md).

Комп’ютер, OSPanel 6+ із PHP 8.1 або альтернативний XAMPP із PHP 8.1, редактор коду та браузер із засобами розробника. Робота виконується на чистому PHP; приклади орієнтовано на PHP 8.1. Потрібні розширення `gd` із підтримкою PNG та `ctype`. Для українських написів у GD потрібні підтримка FreeType і доступний TrueType-шрифт із відповідними символами.

Перед початком повторіть [роботу з файлами](../lab-06/README.md) та [XML/JSON](../lab-08/README.md). Запишіть фактичну версію PHP вебсервера, стан GD, підтримку PNG і FreeType. Середовища Apache та термінала можуть використовувати різні `php.ini`.

## Теоретичні відомості

### GD Graphics Library

GD — бібліотека обробки растрової графіки, доступна через розширення PHP. Вона створює полотна з пікселів, малює фігури й текст, читає та кодує зображення. Розширення може бути вимкнене або відсутнє; перелік підтримуваних форматів залежить від збірки. Перевіряйте `extension_loaded('gd')`, `gd_info()` та `phpinfo()`.

У PHP 8 зображення представлене об’єктом `GdImage`, а не ресурсом старих версій. Об’єкт звільняється, коли на нього більше немає посилань; приклади не покладаються на `imagedestroy()`, яка не виконує звільнення в PHP 8 і позначена застарілою з PHP 8.5.

Координати починаються у верхньому лівому куті: `x` зростає праворуч, `y` — вниз. Для полотна 640×400 останній піксель має координати 639, 399. Фігури та підписи повинні залишатися всередині полотна. Неявне перетворення дробових координат на цілі замінюйте явним округленням.

### Scalable Vector Graphics

SVG — формат векторної графіки на основі XML. Прямокутник або лінія описуються координатами, а не готовою сіткою пікселів. Геометричні фігури можна масштабувати без пікселізації; вбудовані растрові зображення при цьому залишаються растровими.

Для SVG-діаграми GD не потрібне: PHP може сформувати XML-рядок. Кореневий елемент має простір імен `http://www.w3.org/2000/svg`, а `viewBox` задає внутрішню систему координат. Старі посилання на зовнішню DTD не потрібні. Додайте `title` і `desc` для змістовного опису.

Значення підписів екрануйте як XML через `htmlspecialchars($text, ENT_QUOTES | ENT_XML1, 'UTF-8')`. Координати беріть із перевірених чисел, кольори — з фіксованого набору. Не вставляйте довільний SVG-код, обробники подій або зовнішні адреси з введення користувача.

### Основні функції GD

| Функція | Призначення та зауваження |
| --- | --- |
| `imagecreatetruecolor()` | Створення повноколірного полотна; перевіряйте результат |
| `imagecolorallocate()` | Створення кольору за компонентами RGB 0–255 |
| `imagecolorallocatealpha()` | Колір із прозорістю: alpha 0 — непрозорий, 127 — прозорий |
| `imagefill()` | Заливання області від заданої точки |
| `imagefilledrectangle()`, `imageline()` | Стовпці, панелі та осі |
| `imagefilledarc()` | Заповнений сектор; кути вимірюються у градусах |
| `imagestring()` | Напис вбудованим шрифтом; у прикладах використовуємо латиницю |
| `imagettftext()`, `imagettfbbox()` | UTF-8-текст зі шрифтом TrueType та визначення його меж |
| `imagecreatefrompng()`, `imagecreatefromjpeg()` | Декодування наявного зображення; можливі помилки |
| `imagesx()`, `imagesy()` | Розміри декодованого зображення |
| `imagecopyresampled()` | Зміна розміру із перерахунком пікселів |
| `imagepng()`, `imagejpeg()` | Кодування у відповідний формат для відповіді або файла |

`getimagesize()` допомагає попередньо перевірити формат і габарити, але не гарантує успішного декодування та не є повною перевіркою безпечності файла. Крім розміру файла в байтах, обмежуйте кількість пікселів: невеликий стиснений файл може потребувати багато пам’яті після декодування.

### Перелік основних елементів SVG

| Елемент | Використання |
| --- | --- |
| `svg` | Корінь, розміри та `viewBox` |
| `rect`, `circle`, `line` | Стовпці, маркери й осі |
| `path`, `polygon` | Складні контури та багатокутники |
| `text` | Підписи з підтримкою Unicode |
| `g` | Групування та спільні параметри оформлення |
| `title`, `desc` | Назва й опис зображення |
| `defs`, `linearGradient`, `radialGradient` | Повторно використовувані визначення й градієнти |
| `clipPath`, `mask`, `pattern` | Обмеження видимості та заповнення |
| `image` | Вбудовування растрового зображення |

### Масштабування діаграми та HTTP-відповідь

Висота стовпця — частка від найбільшого значення, помножена на висоту області побудови. Якщо всі значення нульові, використовуйте знаменник 1: стовпці матимуть нульову висоту. Ширину області діліть на кількість категорій, а проміжки враховуйте всередині кожного місця для стовпця. Не додавайте проміжок до ширини після ділення всього полотна: останні стовпці вийдуть за межі.

```php
$scale = max(1, max(array_column($data, 'value')));
$barHeight = (int) round($value / $scale * $plotHeight);
$y = $bottom - $barHeight;
```

У круговій діаграмі кут сектора дорівнює `value / sum * 360`. Суму потрібно перевірити перед діленням; у готовому прикладі задано додатні значення 40, 30, 30. Кути обчислюємо з накопиченої суми й округлюємо, щоб останній сектор завершувався на 360°.

PNG-обробник повертає `Content-Type: image/png`, SVG — `image/svg+xml`. Це окремі відповіді, які підключають до HTML через `img`; не додавайте HTML, BOM, пробіли чи діагностичний текст перед байтами PNG. Спочатку перевірте параметри й сформуйте результат, потім надсилайте заголовки. У [common.php](src/common.php) PNG кодується в буфер, а помилки повертаються текстом із кодом 400 або 500, замість пошкодженого зображення.

## Хід роботи

### 1. Підготуйте середовище

1. Запустіть вебсервер проєкту й створіть `C:\xampp\htdocs\lab-09`; інші проєкти не видаляйте. Скопіюйте каталог `src` до проєкту. Зберігайте PHP-файли у UTF-8 без BOM.
2. У тимчасовій діагностичній сторінці викличте **`phpinfo()`**, знайдіть `Loaded Configuration File` та секцію GD. Після перевірки приберіть діагностичну сторінку.
3. Якщо GD вимкнено у XAMPP для Windows, у фактично завантаженому `php.ini` розкоментуйте `extension=gd`, переконайтеся в наявності відповідної DLL та перезапустіть Apache. Для іншого середовища спосіб підключення може відрізнятися.
4. Перевірте `gd_info()` — насамперед підтримку PNG та FreeType. Не вважайте відсутність GD помилкою самого сценарію.
5. Відкрийте `http://web-prog.local/lab-09/src/diagram_png_1.php`. Очікується кругова діаграма з частками 40%, 30%, 30%.

### 2. Дослідіть готові діаграми

1. Перегляньте `diagram_png_1.php`: створення полотна, кольори, розрахунок секторів і виклик `sendPng()`. Змініть значення та поясніть результат. Якщо робите їх змінними, додайте перевірку невід’ємних чисел і додатної суми.
2. Відкрийте `diagram_png_2.php` та `diagram_svg.php`. Вони читають [chart-data.json](src/chart-data.json) і використовують спільну функцію `barLayout()`. Значення категорій A–E: **20, 50, 30, 80, 40**; максимальна висота відповідає D.
3. Перевірте адреси з параметрами `?width=800&height=500`. Допустима ширина — 400–1200, висота — 300–800; типовий розмір — 640×400. Порожні, дробові, масивні та позамежні параметри відхиляються.
4. У вкладці Network порівняйте MIME-типи й розміри відповідей. Збільште масштаб у браузері та порівняйте контури PNG і SVG. У SVG можна прочитати структуру зображення як XML.
5. Створіть HTML-сторінку з двома зображеннями та таблицею вихідних даних. Для кожного `img` задайте змістовний `alt`; таблиця забезпечує доступ до точних значень без залежності від кольору.

```html
<img src="src/diagram_png_2.php?width=640&amp;height=400"
     alt="Активності клубу: A — 20, B — 50, C — 30, D — 80, E — 40">
<img src="src/diagram_svg.php?width=640&amp;height=400"
     alt="Ті самі дані у векторній стовпчастій діаграмі">
```

Ці адреси відповідають HTML-сторінці в корені `lab-09`. Для сторінки всередині `src` приберіть префікс `src/`.

### 3. Самостійне завдання 1: діаграма з файла

Підготуйте власний XML або JSON із 3–10 категоріями: кількість заходів, використання навчальних ресурсів або інші вигадані дані. Збережіть поля `label` і `value` або явно опишіть іншу схему. Відтворіть стовпчасту діаграму у PNG.

- Читайте файл за фіксованим серверним шляхом. Перевіряйте читання, синтаксис, непорожній список, поля та діапазони значень. Для XML використайте безпечний підхід із ЛР 8; DTD і зовнішні сутності не потрібні.
- У готовому JSON-прикладі мітка — 1–10 символів: початкова велика латинська літера, далі великі літери, цифри або пробіли; значення — ціле число 0–1000000. Для власних українських міток змініть перевірку та використайте TrueType-шрифт, а не `imagestring()`.
- Масштабуйте значення до області побудови; осі, нульова позначка, значення стовпців і підписи мають залишатися видимими.
- Додайте підпис: група, вигадане навчальне ім’я автора, дата. Шлях до шрифту задавайте в конфігурації, а не в GET-параметрі. Перевірте існування файла й межі тексту через `imagettfbbox()`.
- Приймайте розміри через перевірені GET-параметри в указаних межах. Для вузького полотна скорочуйте підписи або зменшуйте їхній розмір; повні назви залиште в HTML-таблиці.

### 4. Самостійне завдання 2: SVG-версія

Побудуйте ту саму стовпчасту діаграму у SVG з того самого файла. Використайте однакові масштаб і порядок категорій, додайте українські підписи, `viewBox`, `title`, `desc`. Екрануйте текст як XML. Перевірте, що зміна даних однаково впливає на обидві версії. Статичний [diagram_1.svg](src/diagram_1.svg) показує початкові дані; після зміни JSON динамічна версія оновиться, статичний файл — ні.

### 5. Самостійне завдання 3: водяний знак

Дослідіть [watermark.php](src/watermark.php). Початкове зображення [sample.png](src/images/sample.png) включено до роботи; його можна відтворити командою `php prepare_sample.php` з каталогу `src`. Генератор замінює тільки цей навчальний файл.

1. Відкрийте `watermark.php?image=sample`: отримайте PNG із підписом на контрастній панелі. Код використовує доступний TrueType-шрифт; у Windows перевіряє Arial, в іншому середовищі можна задати шлях змінною `LAB09_FONT` або розмістити законно отриманий `fonts/DejaVuSans.ttf`. Якщо шрифту немає, готовий приклад показує латинський підпис; для власного українського підпису налаштуйте шрифт.
2. Додайте власне навчальне PNG до каталогу `images` й відповідний ключ до серверного списку дозволених файлів. Через HTTP передавайте лише ключ. Не приймайте довільний шлях, `../` або URL.
3. Дотримуйтеся лімітів прикладу: до 2 MiB, від 400×200, не більше 2000 пікселів за кожною стороною та не більше 2 млн пікселів загалом. Перевіряйте декодування; розширення файла не гарантує його формат.
4. Додайте підпис із групою, вигаданим ім’ям і датою. Підберіть розмір та позицію тексту, щоб він не виходив за межі. Для PNG з прозорістю враховуйте `imagealphablending()` та `imagesavealpha()`.
5. Відкрийте `watermark.php?image=sample&download=1`: браузер має завантажити PNG. Заголовок `Content-Disposition` використовує фіксоване ім’я `watermark.png`.
6. Для серверного збереження запустіть `php watermark.php` в терміналі з увімкненим GD. Буде створено або замінено `watermark-output.png` поруч зі сценарієм; вихідне зображення не змінюється. GET-запити готового прикладу повертають результат без запису на сервер. Якщо додаєте збереження через вебформу, виконуйте його через POST із CSRF-токеном за зразком ЛР 7, генеруйте ім’я на сервері й перевіряйте результат запису.

У XAMPP за відсутності PHP у PATH використовуйте `C:\xampp\php\php.exe`. Команди CLI застосовують власну конфігурацію PHP; увімкнення GD для Apache не гарантує його доступності в терміналі.

## Перевірка та очікуваний результат

| Сценарій | Очікувана поведінка |
| --- | --- |
| Кругова діаграма | Три частки 40%, 30%, 30%; зображення без пошкодження |
| Початкові дані PNG і SVG | П’ять стовпців; D найвищий; C має 3/8 його висоти з похибкою округлення |
| 400×300, 640×400, 1200×800 | Правильні розміри; фігури й основні підписи всередині полотна |
| width=399, width=1201, height=299, height=801 | HTTP 400 із текстовим повідомленням |
| width[]=640, width=400.5, width=abc або порожнє значення | HTTP 400 без попереджень PHP у відповіді |
| Один запис у файлі | Один стовпець без ділення на нуль |
| Усі значення дорівнюють нулю | Нульові висоти, осі та підписи залишаються |
| Порожній список, пошкоджений JSON, від’ємне або рядкове value | HTTP 500; дані не змінюються; причина доступна в журналі PHP |
| Український текст і символи `&` та `<` у власних SVG-підписах | Текст збережено, SVG коректний, довільна розмітка не виконується |
| image=../../README.md або image[]=sample | HTTP 400 без читання стороннього файла |
| Перейменований не-PNG, пошкоджене або завелике зображення | Контрольована відмова до видавання готового PNG |
| Шрифт відсутній | У готовому прикладі латинський підпис; український варіант потребує налаштування |
| download=1 | MIME-тип image/png, файл watermark.png із водяним знаком |
| CLI-збереження | watermark-output.png існує та декодується; sample.png не змінено |

Негативні перевірки файла виконуйте на копіях, після них відновлюйте дані. Запишіть фактичні результати; якщо сценарій не вдалося відтворити, зазначте причину. Перевірте HTML-сторінку через [W3C Markup Validation Service](https://validator.w3.org/), вставляючи сформований HTML, а не PHP-код. Перевірте SVG XML-парсером та відкриттям у браузері; XML-розбір сам по собі не підтверджує повну відповідність SVG.

Результат — PNG- і SVG-діаграми з файла та обробник водяного знака зі збереженням і завантаженням. Параметри перевірено, тип відповіді відповідає її вмісту, підписи читабельні, вхідні файли не перезаписуються обробником. Оцінювання здійснюється за критеріями [робочої програми](../../+РПНД%20WП%202023+.docx); окремої бальної шкали тут не запроваджено.

## Вимоги до подання

Подайте вихідні PHP-файли, власні тестові дані, PNG/SVG-результати та PDF-звіт. У звіті зазначте версію PHP, можливості GD і шрифт, опишіть розрахунок масштабу й обмеження параметрів. Додайте підписані знімки трьох завдань, таблицю фактичних перевірок, відповіді на контрольні питання та висновок. Готові приклади відокремте від власних змін. Не публікуйте персональні дані або шрифти без відповідного дозволу на розповсюдження.
