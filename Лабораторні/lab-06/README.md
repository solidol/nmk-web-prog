# Лабораторна робота №6. Робота з файлами та збереження даних

[Перелік усіх робіт](../README.md)

## Мета роботи

Навчитися читати й записувати текстові файли засобами PHP, приймати завантаження через HTML-форму та обробляти помилки. Закріпити роботу з рядками й масивами, створивши невелику «Майстерню текстів» для студентського клубу.

## Обладнання та передумови

Комп’ютер, PHP із XAMPP або окремої інсталяції, редактор коду та браузер. Потрібні знання форм, умов, циклів і функцій із [лабораторної №5](../lab-05/README.md). Для українського тексту потрібне розширення `mbstring`, для визначення MIME-типу — `fileinfo`.

Робота виконується на чистому PHP. Для наведених прикладів використовуйте PHP 8.1 або новішу версію. Запишіть фактичну версію PHP вебсервера; вона може відрізнятися від версії PHP у терміналі.

## Теоретичні відомості

### Читання, запис і шляхи

| Засіб PHP | Призначення | На що звернути увагу |
| --- | --- | --- |
| `file_get_contents()` | Прочитати весь файл у рядок | Помилка повертає `false`; порожній рядок є допустимим результатом |
| `file_put_contents()` | Записати рядок у файл | Повертає кількість записаних байтів або `false`; за замовчуванням замінює вміст |
| `FILE_APPEND` | Додати дані в кінець | Перенос рядка треба додати самостійно |
| `LOCK_EX` | Заблокувати запис для інших узгоджених операцій запису | Не замінює перевірку результату й не захищає автоматично цикл «прочитати — змінити — записати» |
| `fopen()`, `fgets()`, `fclose()` | Відкрити, читати порядково, закрити | Режим `r` — читання, `w` — запис зі стиранням, `a` — дописування |

Перевіряйте помилку через `=== false`: запис нуля байтів не тотожний помилці. Після роботи з відкритим ресурсом викликайте `fclose()`. Щоб прибрати рядок із невеликого текстового файлу, потрібно прочитати дані, сформувати новий вміст і записати його; окремої універсальної функції «видалити рядок» немає.

`__DIR__` задає каталог поточного PHP-файлу й робить шлях незалежним від каталогу запуску. Дані зберігаємо в `storage` поза публічним каталогом `src`. Для перегляду приймаємо лише ім’я встановленого формату. Вираз `file_get_contents($_GET['file'])` небезпечний: користувач не повинен задавати довільний шлях.

### Завантаження через HTTP

Форма передає файл методом POST з `enctype="multipart/form-data"`. PHP створює тимчасовий файл і заповнює `$_FILES`. Послідовність перевірок: структура поля → код `UPLOAD_ERR_OK` → розширення → фактичний розмір → MIME-тип через `finfo` → кодування й вміст. Лише після цього викликають `move_uploaded_file()`.

`accept` у формі допомагає вибрати файл, але не є серверною перевіркою. Полю `$_FILES['myfile']['type']` довіряти не можна. Навіть MIME-тип не гарантує безпечності вмісту: файли не виконують через `include`, а текст виводять з екрануванням. Сервер сам створює ім’я з розширенням `.txt`; початкове ім’я не використовується для збереження.

Ліміт прикладів — 100 КіБ (102400 байтів). PHP також застосовує `upload_max_filesize` і `post_max_size`. Якщо перевищено ліміт усього POST-запиту, масиви форми та завантажень можуть бути порожніми. Приклад тоді пропонує оновити форму та перевірити розмір.

### Український текст і безпечне виведення

`strlen()` рахує байти, `mb_strlen($text, 'UTF-8')` — символи в цьому кодуванні. Для зміни регістру використовуйте `mb_strtolower()`. Перед аналізом перевірте UTF-8 і замініть CRLF та CR на LF.

Текст нотатки може містити `<script>` або HTML-теги. Перед виведенням використовуйте `htmlspecialchars()` з `ENT_QUOTES | ENT_SUBSTITUTE` та UTF-8. У прикладах це робить функція `e()`. Зберігаємо вихідний текст, екрануємо саме під час формування HTML.

Форми запису й імпорту містять CSRF-токен: сервер порівнює його зі значенням у сесії. Готовий [common.php](src/common.php) надає цю перевірку; докладне вивчення сесій передбачене наступною роботою. Після успіху відповідь 303 переводить браузер на сторінку читання, тому звичайне оновлення цієї сторінки не створює ще одного запису.

## Приклади та запуск

Працюйте в окремій папці лабораторної. Не очищуйте `htdocs` та інші каталоги з проєктами.

1. Відкрийте термінал у каталозі `Лабораторні/lab-06`.
2. Перевірте `php -v` і `php -m`: потрібні `mbstring` та `fileinfo`.
3. Запустіть локальний сервер:

```bash
php -S 127.0.0.1:8000 -t src
```

Якщо PHP із XAMPP не додано до PATH, у PowerShell використайте:

```powershell
& C:\xampp\php\php.exe -S 127.0.0.1:8000 -t src
```

Відкрийте `http://127.0.0.1:8000/write_1.php`. Сервер автоматично створить сусідній зі `src` каталог `storage`; потрібне право запису в папку лабораторної. Для зупинки натисніть Ctrl+C. Вбудований сервер призначений для локальної розробки. Якщо використовуєте Apache, його коренем для цього прикладу також має бути `src`, щоб `storage` не був доступний напряму.

| Файл | Що демонструє |
| --- | --- |
| [write_1.php](src/write_1.php) | Форма нотатки, перевірка, запис і перенаправлення |
| [upload.php](src/upload.php) | Імпорт одного текстового файлу |
| [read_file.php](src/read_file.php) | Читання всього файлу й безпечне виведення |
| [read_1.php](src/read_1.php) | Порядкове читання з нумерацією |
| [common.php](src/common.php) | Спільні перевірки, CSRF-токен, формування імен |

Спочатку збережіть нотатку, потім відкрийте посилання «Прочитати порядково». Скопіюйте адресу перегляду та відкрийте її повторно: дані залишаються у файлі. Збережений [приклад users.json](src/users.json) належить до додаткових матеріалів; у цій роботі він не потрібний.

## Хід роботи

### 1. Дослідіть готові приклади

Створіть нотатку з трьох рядків про зустріч клубу. Знайдіть у коді місця перевірки введення, запису та читання. Порівняйте `strlen()` і `mb_strlen()` для слова «Привіт»: очікуємо 12 байтів і 6 символів. Поясніть, навіщо після запису перевіряти результат функції.

### 2. Створіть аналізатор допису

Клуб готує оголошення: потрібно перевірити довжину тексту та повтори слів. На основі `read_file.php` створіть `analyze.php`, який приймає той самий параметр `file` і використовує `selectedPath()`. Додайте на сторінку перегляду посилання на аналізатор.

Покажіть загальну кількість слів, кількість унікальних слів, п’ять найчастіших слів та кількість входжень слова, введеного в GET-формі. Пошук має бути за цілим словом і без урахування регістру. Перед обробкою перевірте, що параметр пошуку є рядком; після нормалізації він має містити рівно одне слово. Порожнє поле означає відсутність пошуку. Передавайте `file` прихованим полем з екрануванням.

Для цієї роботи словом вважаємо послідовність літер, яка може містити внутрішній апостроф; цифри не враховуємо, дефіс розділяє слова. Скористайтеся готовою функцією:

```php
function words(string $text): array
{
    $text = mb_strtolower(str_replace(["’", "ʼ"], "'", $text), 'UTF-8');
    preg_match_all("/\\p{L}+(?:'\\p{L}+)*/u", $text, $matches);
    return $matches[0];
}

$tokens = words($text); // $text уже прочитано й перевірено як UTF-8
$frequencies = array_count_values($tokens);
arsort($frequencies);
$top = array_slice($frequencies, 0, 5, true);
```

Самостійно сформуйте HTML-таблицю результатів. Якщо частоти однакові, порядок цих слів неважливий. Для тексту без слів покажіть нульові підсумки та повідомлення замість порожньої таблиці.

Додайте таблицю «Номер рядка / Символів / Слів». Рахуйте символи з пробілами та розділовими знаками, але без переносу рядка. Кінцевий LF не створює додаткового рядка; внутрішній порожній рядок враховується. Підказка: нормалізуйте переноси, приберіть лише один кінцевий LF, потім застосуйте `explode("\n", $text)`.

### 3. Зберіть архів ідей

Використайте готову форму нотаток і створіть сторінку `archive.php`. Через `glob(storageDir() . '/*.txt')` отримайте список файлів. Передбачте випадок `false` та порожній список. Для кожного файла покажіть його ім’я, розмір у байтах і посилання на перегляд. Для URL використовуйте `rawurlencode()`, для HTML — `e()`.

Збережіть дві нотатки поспіль і переконайтеся, що вони мають різні імена та не перезаписують одна одну. Перезапустіть сервер і перевірте архів. Додайте посилання на архів зі сторінок створення й перегляду.

### 4. Імпортуйте текст і підготуйте звіт

Створіть власний `.txt` із 8–10 рядків: анонс кіноклубу, опис турніру або план екологічної акції. Імпортуйте його через готовий приклад, відкрийте архів та аналізатор.

Створіть `download.php`, який приймає перевірений параметр `file`, повторно обчислює статистику та віддає текстовий звіт: кількість слів, унікальних слів і топ-5. Спільну функцію аналізу можна винести в окремий PHP-файл. Заголовки надсилайте після успішного читання, але до будь-якого виведення:

```php
header('Content-Type: text/plain; charset=UTF-8');
header('Content-Disposition: attachment; filename="report.txt"');
echo $report; // Сформований вами звичайний текст звіту.
exit;
```

Не приймайте довільне ім’я чи шлях звіту з форми. Додайте посилання «Завантажити звіт» до аналізатора.

### 5. Невелике розширення за бажанням

Оберіть одну ідею: підсвічування слів, що повторюються більше трьох разів; підрахунок непорожніх рядків; сортування архіву за розміром. Основна робота завершена після виконання кроків 1–4 та перевірок нижче; розширення необов’язкове.

## Перевірка та очікуваний результат

Контрольний текст (три рядки, UTF-8):

```text
Код єднає!
Код навчає.
Разом створюємо код.
```

Очікуємо 7 слів, 5 унікальних; «код» трапляється 3 рази. У рядках відповідно 2, 2, 3 слова та 10, 11, 20 символів. Пошук «КОД» дає 3, «ко» — 0. Для `п'ять п’ять пʼять` очікуємо одне унікальне слово з частотою 3.

| Перевірка | Очікуваний результат |
| --- | --- |
| Контрольний текст з LF і CRLF | Однакова статистика |
| Нотатка `<b>Ідея</b>` | Теги видно як текст, вони не змінюють оформлення |
| Нотатка лише з пробілів | Повідомлення про помилку, файл не створено |
| Текст `123 !!!` | Нуль слів, аналізатор працює без помилки |
| Порожній файл або файл понад 102400 байтів | Відмова в імпорті |
| Зображення, перейменоване на .txt | Відмова за вмістом |
| Текст у Windows-1251 | Відмова; після збереження в UTF-8 — успішний імпорт |
| Параметр `file=../../README.md` або `file[]=test` | Відмова без читання сторонніх файлів |
| Відсутній або змінений CSRF-токен | Відмова без запису |
| Оновлення сторінки після збереження | Нова нотатка не створюється |
| Завантажений report.txt | Український текст і правильні підсумки |

Результат роботи — невеликий застосунок, у якому можна створити або імпортувати текст, знайти його в архіві, переглянути, проаналізувати й завантажити звіт. Приклади розраховані на одного користувача в локальному середовищі; розмежування доступу між користувачами тут не реалізоване.

Перевірте сформовані HTML-сторінки через [W3C Markup Validation Service](https://validator.w3.org/) шляхом вставлення їхнього HTML-коду. Виправте виявлені помилки.

Подайте вихідні PHP-файли, власний тестовий текст і PDF-звіт. У звіті зазначте версію PHP, коротко опишіть рішення, додайте знімки архіву та аналізатора, таблицю фактичних результатів перевірок і відповіді на контрольні питання. Відокремте власні доповнення від готових прикладів. Використовуйте вигадані навчальні дані.

## Контрольні питання

1. Коли зручно читати файл цілком, а коли — порядково?
2. Чим відрізняються режими `r`, `w` та `a`?
3. Чому результат читання або запису перевіряють через `=== false`?
4. Чим відрізняються кількість байтів і кількість символів українського тексту?
5. Які перевірки потрібні перед `move_uploaded_file()`?
6. Чому не можна використовувати довільний шлях із GET-параметра?
7. Для чого потрібні екранування HTML, CSRF-токен і перенаправлення після POST?
8. Як змінити окремий рядок файла? Які обмеження має файлове зберігання за одночасного доступу?
