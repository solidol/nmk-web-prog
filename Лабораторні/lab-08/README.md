# Лабораторна робота №8. Робота з даними XML та JSON

[Перелік усіх робіт](../README.md)

## Мета роботи

Навчитися читати, створювати й оновлювати структуровані дані у форматах XML та JSON засобами PHP. Використати DOM для XML, масиви для JSON, перевірити помилки розбору й структуру записів та створити каталог із формою додавання за обраним варіантом.

## Обладнання

Основне навчальне середовище — **OSPanel 6+ з PHP 8.1**. Альтернатива — **XAMPP із PHP 8.1**. Налаштування домену, каталогів і консолі наведено в [пам’ятці середовища](../../ENVIRONMENT.md).

Комп’ютер, OSPanel 6+ із PHP 8.1 або альтернативний XAMPP із PHP 8.1, редактор коду та браузер із засобами розробника. Потрібні розширення `dom`, `libxml`, `ctype`; для довжини українського тексту у власній формі — `mbstring`. JSON доступний у PHP 8 як основне розширення. Потрібні знання форм, масивів, файлів і сесій із [ЛР 5](../lab-05/README.md), [ЛР 6](../lab-06/README.md) та [ЛР 7](../lab-07/README.md).

Робота виконується на чистому PHP. Для наведених прикладів використовуйте PHP 8.1. Запишіть фактичну версію PHP вебсервера; вона може відрізнятися від версії PHP у терміналі.

## Теоретичні відомості

### Що таке XML?

XML (eXtensible Markup Language) — текстова мова розмітки для представлення структурованих даних. Документ має один кореневий елемент, узгоджені відкривальні й закривальні теги та правильну вкладеність. Імена чутливі до регістру. Значення атрибутів беруть у лапки; спеціальні символи тексту кодують, наприклад `&` як `&amp;` та `<` як `&lt;`.

У прикладах використовуємо одну структуру: список `people`, записи `person`, поля `name` і `age`. Це вигадані навчальні дані.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<people>
  <person><name>Олена</name><age>20</age></person>
  <person><name>Тарас</name><age>25</age></person>
  <person><name>Клуб &lt;Код&gt; &amp; друзі</name><age>0</age></person>
</people>
```

XML зберігає текст полів, тому вік після читання потрібно перевірити й перетворити на число. Правильний синтаксис не гарантує потрібних полів або допустимих значень. Для цієї роботи структуру перевіряємо кодом; XSD не є обов’язковим.

### Що таке JSON?

JSON (JavaScript Object Notation) — текстовий формат обміну даними. Об’єкт містить пари «ім’я — значення», масив — упорядковану послідовність значень. Підтримуються рядки, числа, `true`, `false`, `null`, об’єкти й масиви. Рядки та імена властивостей беруть у подвійні лапки; коментарі й кінцеві коми стандартом не передбачені.

Ті самі записи у JSON:

```json
[
  {"name": "Олена", "age": 20},
  {"name": "Тарас", "age": 25},
  {"name": "Клуб <Код> & друзі", "age": 0}
]
```

Тут `age` — число, а не рядок `"20"`. Файли зберігайте в UTF-8. JSON не є PHP-кодом: не використовуйте `eval()` для його читання. Розбір формату, перевірка даних і HTML-екранування — три окремі операції.

### Робота з XML у PHP

`DOMDocument` представляє документ як дерево вузлів. `load()` читає файл, `loadXML()` — рядок; обидва повертають `bool`. Викликайте їх через створений об’єкт, а не статично. `getElementsByTagName()` повертає `DOMNodeList` усіх відповідних нащадків; відсутній `item(0)` дає `null`.

Скористайтеся [common.php](src/common.php): `readText()` перевіряє читання, `parseXml()` збирає помилки libxml і відновлює попередній режим їх обробки, `peopleFromXml()` перевіряє корінь, поля та значення. Порожній файл не передається парсеру. Неправильні дані спричиняють виняток, який обробляє сторінка.

Спрощений обхід документа після перевірки структури:

```php
<?php
require __DIR__ . '/common.php';
try {
    $dom = parseXml(readText(__DIR__ . '/persons.xml'));
    peopleFromXml($dom); // Перевірка структури перед обходом.
    foreach ($dom->getElementsByTagName('person') as $person) {
        $name = $person->getElementsByTagName('name')->item(0);
        echo '<p>' . e($name->textContent) . '</p>';
    }
} catch (RuntimeException $exception) {
    http_response_code(500);
    echo '<p>' . e($exception->getMessage()) . '</p>';
}
```

Повну HTML-сторінку з таблицею наведено в [прикладі читання XML](src/read_persons_xml.php).

Для створення тексту використовуйте `createTextNode()`, щоб символи `&` і `<` не трактувалися як розмітка чи посилання на сутність:

```php
<?php
$dom = new DOMDocument('1.0', 'UTF-8');
$dom->formatOutput = true;
$root = $dom->createElement('people');
$dom->appendChild($root);
$person = $dom->createElement('person');
foreach (['name' => 'Клуб <Код> & друзі', 'age' => '0'] as $key => $value) {
    $field = $dom->createElement($key);
    $field->appendChild($dom->createTextNode($value));
    $person->appendChild($field);
}
$root->appendChild($person);
$bytes = $dom->save(__DIR__ . '/persons-demo.xml');
if ($bytes === false) {
    throw new RuntimeException('Не вдалося записати XML.');
}
```

`save()` повертає кількість **байтів** або `false`, а не кількість символів чи фіксоване число. `saveXML()` повертає XML-рядок. Не додавайте записи простим дописуванням тексту після кореневого елемента: змінюйте дерево та зберігайте цілий документ.

У навчальному форматі DTD не дозволено. Не вмикайте `LIBXML_NOENT`, `LIBXML_DTDLOAD` чи підстановку зовнішніх сутностей. `LIBXML_NONET` обмежує мережевий доступ, але сам по собі не є повним захистом від читання локальних ресурсів. Приклад залишає небезпечні можливості вимкненими й відхиляє документи з DTD. Не приймайте від користувача шлях файла або URL для парсера.

### Робота з JSON у PHP

`json_decode($json, true, 512, JSON_THROW_ON_ERROR)` повертає асоціативні масиви; без другого аргументу JSON-об’єкти стають `stdClass`. `JSON_THROW_ON_ERROR` дає `JsonException` за неправильного JSON. Навіть коректний `null` або об’єкт може не відповідати очікуваному списку.

У [прикладі читання JSON](src/read_persons_json.php) окремо перевірено, що корінь — JSON-масив; після цього перевірено поля записів. Це дає змогу відрізнити порожній список `[]` від об’єкта `{}`.

```php
<?php
require __DIR__ . '/common.php';
try {
    $json = readText(__DIR__ . '/persons.json');
    $decoded = json_decode($json, false, 512, JSON_THROW_ON_ERROR);
    if (!is_array($decoded)) {
        throw new RuntimeException('Очікується JSON-масив.');
    }
    $people = validatePeople(json_decode($json, true, 512, JSON_THROW_ON_ERROR));
    foreach ($people as $person) {
        echo '<p>' . e($person['name']) . ': ' . $person['age'] . '</p>';
    }
} catch (JsonException $exception) {
    echo '<p>Некоректний JSON або UTF-8.</p>';
} catch (RuntimeException $exception) {
    echo '<p>' . e($exception->getMessage()) . '</p>';
}
```

`json_encode()` серіалізує перевірений масив. `JSON_UNESCAPED_UNICODE` залишає українські літери читабельними, `JSON_PRETTY_PRINT` додає відступи. Вони не захищають HTML-виведення. Після вилучення елемента списку застосуйте `array_values()`, щоб послідовні числові ключі знову кодувалися як JSON-масив.

```php
$people[] = ['name' => 'Новий учасник', 'age' => 18];
$json = json_encode(validatePeople($people),
    JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT | JSON_THROW_ON_ERROR);
$content = $json . "\n";
$bytes = file_put_contents(__DIR__ . '/persons-demo.json', $content, LOCK_EX);
if ($bytes === false || $bytes !== strlen($content)) {
    throw new RuntimeException('Не вдалося повністю записати JSON.');
}
```

Це продовження успішного читання; кодування й запис також помістіть у `try/catch`. У разі пошкодженого вхідного файла не замінюйте його порожнім списком. `LOCK_EX` під час запису не захищає весь цикл «прочитати — змінити — записати» від одночасних запитів. Роботу виконуємо локально для одного користувача; узгоджене блокування всього циклу та атомарна заміна файла — окремі завдання.

## Хід роботи

1. Запустіть Apache. Створіть окремий каталог `lab-08` у публічному каталозі OSPanel; для альтернативного XAMPP — `C:\xampp\htdocs\lab-08`; інші файли в `htdocs` не видаляйте. Скопіюйте туди каталог `src` і відкривайте сторінки через `http://web-prog.local/lab-08/src/`.
2. Перевірте версію PHP та потрібні розширення. Перегляньте XML і JSON у редакторі, зіставте записи, тип віку й спосіб представлення спеціальних символів.
3. Запустіть `read_persons_xml.php` та `read_persons_json.php`. Обидві таблиці мають показати ті самі три записи. Дослідіть спільні функції в `common.php`; власні класи створювати не потрібно.
4. Виконайте приклад обходу DOM із теоретичного розділу. Поясніть відмінність `load()` і `loadXML()`, ролі `documentElement`, `DOMNodeList` та `textContent`. Перетворіть виведення на власну таблицю або перелік.
5. Запустіть генератори з термінала в каталозі `src`: `php write_persons_xml.php` та `php write_persons_json.php`. У XAMPP за відсутності PHP у PATH використайте `C:\xampp\php\php.exe`. Генератори **замінюють навчальні persons.xml і persons.json**; перед експериментами збережіть копії. Через браузер запис цими скриптами заборонений, щоб GET не змінював дані.
6. Порівняйте повідомлення про запис із розміром файла в байтах. Після повторного читання переконайтеся, що «Клуб <Код> & друзі» відображається звичайним текстом, а вік `0` не сприймається як помилка.
7. Зробіть копії файлів. Додайте четвертий запис до XML через дерево DOM, а до JSON — через масив. Збережіть, повторно прочитайте й порівняйте результат. Не використовуйте `FILE_APPEND` для додавання запису до цілого XML/JSON-документа.
8. Виконайте індивідуальне завдання за одним із **10 варіантів нижче**. Визначте щонайменше три змістові поля та стабільний унікальний `id` запису. Наприклад, для бібліотеки: `id`, `title`, `author`, `year`. Створіть не менше трьох вигаданих записів; укажіть типи, обов’язковість і допустимі межі кожного поля.
9. Реалізуйте XML-версію: файл `book.xml` для бібліотеки або відповідне темі ім’я, сторінку табличного перегляду та форму додавання. Для іншого варіанта змініть корінь, назви елементів і перевірки; допоміжні функції прикладу розраховані саме на `people/name/age`.
10. В обробнику перевірте POST, CSRF-токен із сесії за зразком ЛР 7, типи та значення полів. Рядки нормалізуйте через `trim()`; довжину українського тексту перевіряйте через `mb_strlen()`. Межі задайте відповідно до власної схеми. Відомі імена елементів задавайте кодом, а значення додавайте текстовими вузлами. Не створюйте теги з довільного введення.
11. Перевірте наявний файл перед зміною. Додавайте запис до списку, не перезаписуючи попередні записи; `id` генеруйте на сервері, наприклад через `bin2hex(random_bytes(8))`, із перевіркою відсутності збігу. Для нового каталогу створіть файл явно під час підготовки, а не замість пошкодженого документа.
12. Перевірте результат запису. Показуйте успіх лише після збереження; після успішного POST виконайте перенаправлення `303` на сторінку каталогу та `exit`. За помилки збережіть несекретне введення в формі й покажіть повідомлення. Усі дані в HTML екрануйте; шлях сховища задайте через `__DIR__`, не через параметр форми.
13. **Завдання підвищеної складності:** додайте редагування запису за `id`. GET-посилання лише відкриває форму, POST із CSRF-токеном зберігає зміни. Невідомий `id` не створює новий запис. Посилання для переходу має використовувати URL-кодування ідентифікатора й HTML-екранування атрибутів.
14. Реалізуйте JSON-версію того самого каталогу з тими самими полями, перевірками й операціями. Збережіть обидві версії, наприклад у каталогах `xml` та `json`. Якщо виконували редагування, перенесіть його в обидві версії. Порівнюйте дані, а не буквальний вміст файлів: форматування може відрізнятися.
15. Виконайте перевірки з таблиці нижче. Перевірте сформований HTML через [W3C Markup Validation Service](https://validator.w3.org/) шляхом вставлення коду відповіді браузера. PHP-шаблони у валідатор не передають. Виправте розмітку, зв’язки підписів із полями та назви кнопок.
16. У своєму навчальному репозиторії `web-progr` на GitHub створіть папку `lab 08` або використайте узгоджену викладачем назву. Розмістіть кінцеві файли обох версій, тестові дані й інструкцію запуску. Використовуйте вигадані дані; секрети та ідентифікатори сесій не публікуйте.
17. Підготуйте PDF-звіт: тема, мета, версія PHP, номер варіанта, схема полів, опис файлів, власний код і підписані знімки ключових етапів. Додайте таблицю фактичних результатів, відповіді на контрольні питання, висновок і посилання на папку репозиторію. Готові приклади відокремте від власних доповнень. Збережіть звіт у навчальному репозиторії.

### Перевірка та очікуваний результат

| Сценарій | Очікувана поведінка |
| --- | --- |
| Початкові приклади XML і JSON | Однакові три записи, українські літери відображено правильно |
| Назва з `&`, `<`, лапками; вік 0 | Значення збережено без спотворення; HTML-теги не виконуються |
| Порожній список `people` або JSON `[]` | Повідомлення «Записів немає» |
| Відсутній або порожній файл | Повідомлення про помилку без перезаписування даних |
| Незакритий XML-тег; зайва кома в JSON | Контрольована відмова в розборі |
| XML із DTD | Відмова; зовнішні сутності не підставляються |
| Інший корінь XML; JSON `{}` або `null` | Відмова за невідповідною структурою |
| Відсутнє поле; повторне XML-поле; неправильний тип JSON-поля | Відмова до показу таблиці або запису |
| Вік -1, 121, дробове число чи рядок у JSON | Відмова за правилами прикладу; у власному каталозі перевірте свої межі |
| Додавання двох записів поспіль | Обидва збережено, попередні записи залишилися |
| Порожнє поле або масив замість рядка POST | Помилка поля без warning чи TypeError |
| Відсутній або неправильний CSRF-токен | Відмова без зміни файла |
| Оновлення сторінки після додавання | Новий запис повторно не додається |
| Файл недоступний для запису | Повідомлення про збій без повідомлення про успіх |
| Редагування невідомого id, якщо реалізовано | Відмова без створення запису |

Результат — дві версії каталогу за обраним варіантом: перегляд і додавання, а за виконання підвищеної складності — також редагування. Вхідні дані перевірено, помилки не маскуються успішним повідомленням, український текст і спеціальні символи проходять цикл «запис — читання» без втрат. Для невиконаного сценарію зазначте причину; не записуйте вигаданих результатів.

Оцінювання здійснюється за критеріями [робочої програми](../../+РПНД%20WП%202023+.docx); окремої бальної шкали тут не запроваджено.

10. Чому екранування для XML не замінює екранування для HTML?

Генератори демонструють формування списку з двох записів і додавання третього перед збереженням. Вони не реалізують студентську вебформу й не доповнюють наявний файл під час повторного запуску. Права читання та запису потрібні користувачу, від якого працює відповідний процес PHP.
