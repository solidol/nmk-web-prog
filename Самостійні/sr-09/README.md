# Формат передачі даних JSON

## Мета

Читати й створювати JSON, перевіряти структуру декодованих даних та розрізняти синтаксичну коректність і допустимість значень. Самостійна робота — 2 год.

## Теоретичний матеріал

JSON — текстовий формат обміну даними, незалежний від мови програмування. Він підтримує об'єкти, масиви, рядки, числа, логічні значення та `null`. Імена властивостей об'єкта записують у подвійних лапках. Коментарі та зайва кома після останнього елемента не входять до стандартного синтаксису. Функції, класи й дата як окремий тип у JSON відсутні.

Об'єкт задає пари «ім'я — значення», а масив — упорядковану послідовність. У PHP `json_decode()` може перетворити JSON-об'єкт на `stdClass` або асоціативний масив. Другий аргумент `true` обирає масив. Після декодування потрібно знати, яку форму очікує програма: доступ через `->title` і через `['title']` належить до різних структур.

```php
<?php
$json = '{"title":"PHP","hours":2}';
try {
    $data = json_decode($json, true, 512, JSON_THROW_ON_ERROR);
    if (!is_array($data)
        || !isset($data['title'], $data['hours'])
        || !is_string($data['title'])
        || !is_int($data['hours'])
        || $data['hours'] < 1) {
        throw new InvalidArgumentException('Некоректні поля');
    }
    echo json_encode($data, JSON_UNESCAPED_UNICODE | JSON_THROW_ON_ERROR);
} catch (JsonException | InvalidArgumentException $error) {
    echo 'Дані не прийнято';
}
```

Це приклад для PHP 8.1+ із навчальними даними, а не зміна годин програми. `JSON_THROW_ON_ERROR` дозволяє обробляти помилки через виняток. `JSON_UNESCAPED_UNICODE` робить українські літери читабельними, але не змінює зміст JSON. Без перевірки помилок або винятків невдале декодування можна сплутати з допустимим значенням `null`.

Коректний JSON ще не є коректним запитом. Наприклад, `{"hours":"два"}` має допустимий синтаксис, але не відповідає очікуваному цілому числу. Перевіряють обов'язкові поля, типи, межі та правила предметної області. Додатково визначають політику щодо невідомих полів: ігнорувати їх чи відхиляти запит. Автоматично записувати весь отриманий об'єкт у модель небезпечно.

Послідовний масив PHP із ключами від нуля кодується як JSON-масив. Після вилучення елементів ключі можуть мати пропуски, і результат кодування стане об'єктом. Якщо контракт вимагає список, перед кодуванням доречно перевірити ключі та за потреби застосувати `array_values()`. Великі числові ідентифікатори слід передавати узгоджено, часто рядками, щоб клієнт не втрачав точність.

У HTTP для JSON використовують тип вмісту `application/json`. PHP читає JSON-тіло окремо від `$_POST`; Laravel надає відповідні засоби об'єкта запиту. JSON не забезпечує шифрування або перевірку прав. Для виведення отриманого тексту всередині HTML потрібне екранування; вставляти JSON безпосередньо у скрипт як довільний текст не слід.

## Завдання

1. Перевірте правильний документ, зайву кому, відсутнє поле та рядок замість числа.
2. Порівняйте декодування з другим аргументом `true` і `false`.
3. Закодуйте список до та після вилучення середнього елемента, потім застосуйте `array_values()`.
