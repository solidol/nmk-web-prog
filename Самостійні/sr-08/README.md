# Засоби PHP для роботи з СУБД PostgreSQL

## Мета

Порівнювати засоби доступу PHP до PostgreSQL та будувати параметризований запит. Самостійна робота — 2 год. PostgreSQL розглядається як додаткова СУБД; основною в дисципліні залишається MariaDB.

## Теоретичний матеріал

PHP взаємодіє з PostgreSQL через розширення `pgsql` або драйвер `PDO_PGSQL`. Перше надає функції родини `pg_*`, друге реалізує спільний інтерфейс PDO. Потрібний драйвер має бути встановлений і ввімкнений саме в тому середовищі, де виконується код. Наявність PDO без PostgreSQL-драйвера недостатня для такого з'єднання.

З'єднання визначається адресою сервера, портом, назвою бази та обліковими даними. У PDO ці параметри частково задають рядком DSN із префіксом `pgsql:`. Пароль не записують у вихідний код: його отримують із локальної конфігурації чи оточення. Обліковий запис застосунку повинен мати лише потрібні права, а не повноваження адміністратора СУБД.

Основний захист від SQL-ін'єкції — відокремлення тексту команди від значень. PDO використовує `prepare()` та `execute()`, а `pg_query_params()` приймає SQL із позиційними позначками `$1`, `$2` і масив параметрів. Підставляти введений текст конкатенацією не можна. HTML-екранування не робить SQL безпечним, оскільки це інший синтаксичний контекст.

Нижче наведено фрагмент для вже створеного об'єкта `$pdo`, підключеного до навчальної PostgreSQL. Передумова — таблиця `courses` із колонками `id` та `title` і тестовий запис із `id = 1`.

```php
$pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
$statement = $pdo->prepare(
    'SELECT id, title FROM courses WHERE id = :id'
);
$statement->execute(['id' => 1]);
$course = $statement->fetch(PDO::FETCH_ASSOC);
if ($course === false) {
    echo 'Курс не знайдено';
} else {
    echo htmlspecialchars($course['title'], ENT_QUOTES, 'UTF-8');
}
```

У вебобробнику ідентифікатор спочатку перевіряють як допустиме ціле число. Параметризувати можна значення, але не назви таблиць, колонок чи напрям сортування. Такі структурні елементи, якщо вони залежать від вибору користувача, визначають за фіксованим списком дозволених варіантів.

Результат `fetch()` може бути `false`, коли рядків немає. Це відрізняється від помилки з'єднання чи SQL, для яких у прикладі налаштовано винятки. Технічні подробиці винятку записують у захищений журнал, а клієнту повертають зрозуміле повідомлення без паролів і внутрішніх адрес. Порожній результат не слід маскувати загальною помилкою сервера.

Кілька залежних змін об'єднують транзакцією: початок, виконання команд, підтвердження або відкат. PDO уніфікує виклики, але не усуває відмінностей SQL між PostgreSQL і MariaDB. Типи колонок, генерація ідентифікаторів та специфічні оператори потребують окремої перевірки. Перенесення застосунку не зводиться до заміни префікса DSN.

## Завдання

1. Порівняйте `pgsql` та `PDO_PGSQL`: з'єднання, параметри, читання результату.
2. Опишіть результати пошуку наявного й відсутнього курсу та помилки з'єднання.
3. Поясніть, що потрібно перевірити під час перенесення запиту на MariaDB.

## Вимоги до результату

Подайте порівняння та пояснення фрагмента. Якщо PostgreSQL доступна, додайте результати виконання; інакше явно позначте їх як очікувані. Не включайте облікових даних.
