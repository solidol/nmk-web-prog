# Шаблонізатор Blade

## Мета

Формувати HTML за допомогою Blade, передавати дані в подання та застосовувати екранування й засоби побудови форм. Самостійна робота — 2 год. Матеріал стосується Laravel 10.x із навчального проєкту.

## Теоретичний матеріал

Blade — шаблонізатор Laravel. Файли мають закінчення `.blade.php` і зазвичай зберігаються в `resources/views`. Контролер готує дані й повертає подання через `view()`, а шаблон визначає розмітку. Blade компілює шаблони у PHP та кешує скомпільовані файли. Це не означає автоматичного кешування всіх персональних HTML-відповідей.

Запис `{{ $title }}` виводить значення з HTML-екрануванням. Так спеціальні символи в назві курсу відображаються як текст. Запис `{!! $html !!}` вимикає цю обробку; для довільного введення користувача він створює ризик XSS. HTML-екранування не замінює перевірки URL, правил SQL або спеціального способу передавання даних у JavaScript.

Для локального досліду додайте GET-маршрут у `routes/web.php` окремої навчальної копії Laravel. Маршрут передає звичайний масив і не потребує підключення до MariaDB:

```php
Route::get('/study-courses', function () {
    return view('study-courses', [
        'courses' => ['PHP', 'MariaDB', 'Laravel']
    ]);
});
```

У файлі `resources/views/study-courses.blade.php` розмістіть шаблон:

```blade
<h1>Навчальні курси</h1>
<ul>
    @forelse ($courses as $course)
        <li>{{ $course }}</li>
    @empty
        <li>Курсів поки немає</li>
    @endforelse
</ul>
```

Директива `@forelse` поєднує обхід колекції з обробленням порожнього набору. Це дозволяє явно визначити обидва стани інтерфейсу. У шаблоні не потрібно виконувати SQL-запит або вирішувати, які записи дозволено бачити користувачу: ці дані готують до виклику подання. Інакше оформлення стає залежним від правил доступу й структури сховища.

Спільний каркас сторінок будують через успадкування шаблонів із `@extends`, `@section`, `@yield` або через компоненти Blade. Частковий шаблон підключають через `@include`. Повторно використовувана картка курсу має отримувати чіткий набір даних. Компонент не повинен непомітно змінювати базу під час відображення.

POST-форма в маршрутах із сеансовим CSRF-захистом має містити `@csrf`. Після серверної валідації `@error('title')` допомагає показати повідомлення для поля, а `old('title')` — відновити попереднє введення. Перевірка HTML-атрибутом `required` покращує взаємодію, проте не замінює серверних правил: клієнт може надіслати запит поза формою.

Зміна шаблону перевіряється не лише на правильних даних. Порожній список, довга назва та символи `<`, `>`, `&` показують, чи витримує подання реальні варіанти вмісту. Показувати кнопку лише адміністратору корисно для інтерфейсу, але відповідний маршрут також має перевіряти повноваження.

## Завдання

1. Відтворіть маршрут і шаблон, перевірте звичайний та порожній список.
2. Додайте назву `PHP <основи>` й поясніть різницю між HTML-кодом відповіді та видимим текстом.
3. Спроєктуйте форму назви курсу з CSRF-токеном, відновленням введення та місцем повідомлення про помилку.

## Вимоги до результату

Подайте маршрут, шаблон і результати перевірок. Для форми поясніть, які дії повинен виконувати обробник; не стверджуйте, що сам шаблон забезпечує збереження. Зазначте версію Laravel.
