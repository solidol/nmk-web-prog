# Копіювання та переміщення файлів

## Мета

Розрізняти файлові операції PHP, перевіряти їхній результат і визначати умови безпечної роботи із завантаженнями. Самостійна робота — 2 год.

## Теоретичний матеріал

Копіювання створює окремий файл із вмістом джерела, а переміщення змінює місце його розташування. У PHP `copy()` копіює файл, `rename()` перейменовує або переміщує його, а `move_uploaded_file()` призначена для файлів, завантажених через HTTP POST. Обирати функцію потрібно за походженням файла та очікуваним результатом, а не лише за схожістю назв.

Функції повертають ознаку успіху, яку слід перевіряти. Причинами невдачі можуть бути відсутність джерела, недостатні права, недоступний каталог або обмеження середовища. Наявність рядка з адресою файла ще не означає, що файл існує. Відносний шлях залежить від робочого каталогу; для навчальних прикладів зручно прив'язати його до `__DIR__`.

Наведений фрагмент виконайте в окремій локальній папці. Поруч зі скриптом заздалегідь створіть `sample.txt`; файл `sample-copy.txt` має бути відсутній. Користувацькі параметри тут не застосовуються.

```php
<?php
$source = __DIR__ . '/sample.txt';
$target = __DIR__ . '/sample-copy.txt';
if (!is_file($source) || file_exists($target)) {
    throw new RuntimeException('Перевірте навчальні файли');
}
if (!copy($source, $target)) {
    throw new RuntimeException('Копіювання не виконано');
}
echo 'Копію створено' . PHP_EOL;
```

Після копіювання джерело залишається. Якщо ціль уже існує, `copy()` може її перезаписати; у прикладі це попередньо перевіряється. Така перевірка придатна для однокористувацького досліду, але не усуває змагання між паралельними процесами. У реальному сервісі потрібні унікальні імена та спосіб створення, який виключає небажаний перезапис.

Для завантаження браузером спочатку перевіряють код помилки в `$_FILES`, розмір і дозволений тип вмісту. Назва та MIME-тип, заявлені клієнтом, не є достатнім підтвердженням. `move_uploaded_file()` перевіряє походження тимчасового файла як HTTP-завантаження, але не встановлює його безпечність. Файл із допустимим розширенням може містити зовсім інші дані.

Сервер має сам обирати каталог зберігання та формувати ім'я. Довільні шляхи з форми, включно з `../`, створюють ризик виходу за межі дозволеної папки. Одного видалення небажаного фрагмента з рядка недостатньо: потрібна перевірка кінцевого шляху й прав доступу. Завантаження доцільно зберігати поза публічним каталогом або забороняти виконання коду в сховищі.

Переміщення між файловими системами не слід вважати універсально атомарним. Копіювання з подальшим видаленням — дві операції, між якими можлива помилка. Результат потрібно підтвердити до видалення джерела. Якщо відомості про файл записуються в MariaDB, транзакція бази даних сама по собі не скасує файлову операцію: необхідний план узгодження станів.

## Завдання

1. Виконайте копіювання в навчальній папці й порівняйте вміст обох файлів.
2. Перевірте відсутнє джерело та повторний запуск із наявною копією.
3. Опишіть послідовність перевірок завантаження й відмінність `rename()` від `move_uploaded_file()`.

## Вимоги до результату

Подайте код, результати трьох сценаріїв та схему приймання файла. Поясніть, чому контроль шляху, типу вмісту та прав доступу є окремими перевірками. Реальні документи для досліду не використовуйте.
