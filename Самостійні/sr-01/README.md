# Мови формування вебсторінок. Python

## Мета

Розрізняти ролі мов у вебзастосунку та пояснювати, як Python формує HTTP-відповідь. Самостійна робота — 2 год.

## Теоретичний матеріал

Вебсторінка поєднує структуру, оформлення та поведінку. HTML описує заголовки, посилання, форми й інші елементи документа. CSS визначає їхній вигляд, а JavaScript у браузері обробляє події та змінює документ. PHP і Python можуть працювати на сервері: отримувати запит, перевіряти дані, звертатися до бази даних і формувати відповідь. Браузер отримує результат їхньої роботи, а не серверний вихідний код.

Динамічна сторінка створюється з урахуванням адреси запиту, параметрів і стану застосунку. Наприклад, для каталогу курсів сервер добирає записи з бази даних, передає їх шаблону й повертає HTML. Інший клієнт може отримати ті самі записи як JSON. Отже, мова серверної логіки не визначає єдиний формат відповіді. HTTP пов'язує клієнт і сервер незалежно від мов їх реалізації.

Python використовує відступи для позначення блоків. Імена змінних не мають префікса `$`, а завершувати кожну інструкцію крапкою з комою не потрібно. Списки придатні для впорядкованих наборів, словники — для пар «ключ — значення». У PHP схожі завдання часто виконує масив. Подібність призначення структур не означає однакових правил доступу чи перетворення типів.

У Python вебфреймворк Django пов'язує URL із функцією або класом обробника. Обробник отримує об'єкт запиту та повертає відповідь. Шаблон містить розмітку і місця підстановки даних. Це дозволяє змінювати оформлення без переписування запитів до бази. Django тут розглядається для порівняння: основним стеком дисципліни залишаються PHP, MariaDB і Laravel.

Наведений приклад для Python 3 демонструє лише формування фрагмента HTML у консолі; він не запускає вебсервер:

```python
from html import escape

courses = ["PHP", "MariaDB", "Laravel"]
items = "".join(f"<li>{escape(name)}</li>" for name in courses)
print(f"<ul>{items}</ul>")
```

Функція `escape()` перетворює спеціальні символи для HTML. Якщо назва курсу містить `<` або `&`, вони мають відобразитися як текст. Перевірка вхідних даних і екранування результату виконують різні завдання: перша встановлює допустимість значення, друге забезпечує коректне включення в певний контекст. Для SQL потрібні параметризовані запити, а не HTML-екранування.

## Завдання

1. Побудуйте схему отримання сторінки каталогу: браузер, HTTP-запит, обробник, база даних, шаблон, відповідь.
2. Для HTML, CSS, JavaScript, PHP і Python запишіть місце виконання та одну функцію в цій схемі.
3. Виконайте приклад, додайте назву `HTML <основи>` і поясніть отриманий рядок. Опишіть, що ще потрібно для видавання його через HTTP.

## Вимоги до результату

Подайте схему, порівняння мов, код і результат запуску. Поясніть відмінність між сформованим HTML та його відображенням браузером. Зазначте використану версію Python; установлення Django для цього завдання не потрібне.
