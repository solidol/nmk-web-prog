# Стандартний клас

## Мета

Пояснювати призначення `stdClass`, створювати прості об'єкти даних і визначати межі їх застосування. Самостійна робота — 2 год.

## Теоретичний матеріал

У цій темі стандартним класом названо вбудований `stdClass` PHP. Це універсальний порожній клас для об'єктів із властивостями. Він не є спільним предком усіх класів PHP: власний клас без `extends` не стає його нащадком. `stdClass` зручний для передавання невеликого набору даних, коли окрему поведінку об'єкта не визначають.

Об'єкт створюють через `new stdClass()`, а властивості читають і записують оператором `->`. Їх можна додавати під час виконання. Для `stdClass` динамічні властивості дозволені; це не слід переносити на будь-який користувацький клас. Починаючи з PHP 8.2, створення таких властивостей у звичайних класах без відповідних винятків є застарілим підходом. У власних класах властивості варто оголошувати явно.

```php
<?php
$course = new stdClass();
$course->title = 'PHP';
$course->hours = 2;
$same = $course;
$same->hours = 3;
$copy = clone $course;
$copy->hours = 4;
echo $course->hours . PHP_EOL; // 3
echo $copy->hours . PHP_EOL;   // 4
```

Присвоєння об'єкта іншій змінній не створює незалежної копії: обидві змінні позначають той самий об'єкт. Тому зміна через `$same` видима через `$course`. Оператор `clone` створює новий об'єкт, але копіювання є поверхневим: вкладені об'єкти можуть залишатися спільними. Наведені числа — лише демонстрація стану, а не навчальне навантаження.

Інший шлях отримання `stdClass` — декодування JSON-об'єкта без параметра асоціативного масиву. Для `json_decode('{"title":"PHP"}')` властивість доступна як `->title`. Якщо передати другим аргументом `true`, буде масив. Змішування цих двох форм призводить до помилок доступу, тому формат потрібно зафіксувати на межі компонента.

Масив можна перетворити на об'єкт через `(object)`, але це не додає методів перевірки та не перетворює дані на повноцінну модель курсу. Довільна властивість `hours` сама по собі не гарантує цілого додатного числа. Валідація має передувати використанню даних. Невідомі поля з HTTP-запиту не слід безконтрольно переносити до внутрішнього об'єкта.

Перевірка `isset($course->title)` повертає хибність і для відсутньої властивості, і для значення `null`. Коли ці стани мають різний зміст, потрібна окрема перевірка існування властивості, наприклад `property_exists()`. Пряме читання невідомого поля може дати попередження. Контракт даних повинен визначати, які поля обов'язкові, а які можуть бути порожніми.

Для об'єкта з правилами, наприклад забороною від'ємної тривалості, краще створити власний клас із конструктором і методами. У Laravel модель Eloquent додатково описує взаємодію з базою даних; `stdClass` таких можливостей не має. Простота контейнера доречна лише тоді, коли від нього не очікують прихованих гарантій.

## Завдання

1. Виконайте приклад і поясніть відмінність присвоєння від клонування.
2. Створіть об'єкт із JSON, потім отримайте асоціативний масив із тих самих даних.
3. Порівняйте відсутню властивість, `null` і порожній рядок. Визначте, який стан означає «назву ще не задано» у вашому контракті.

## Вимоги до результату

Подайте код, результати перевірок та коротке обґрунтування вибору між `stdClass`, масивом і власним класом. Поясніть, де виконуватиметься перевірка полів курсу.
