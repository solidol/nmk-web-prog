# Конструктори класів

## Мета

Створювати об'єкти з коректним початковим станом і пояснювати роль конструктора, перевірки аргументів та передавання залежностей. Самостійна робота — 2 год.

## Теоретичний матеріал

Конструктор `__construct()` викликається під час звичайного створення об'єкта через `new`. Він приймає початкові дані та встановлює стан, з яким об'єкт може працювати. Це дозволяє уникнути ситуації, коли після створення потрібно пам'ятати про кілька обов'язкових присвоєнь. Конструктор не повертає створений об'єкт через `return` і не має оголошеного типу результату.

Початкові дані мають відповідати правилам класу. Тип `string` ще не гарантує непорожньої назви, а тип `int` — додатної тривалості. Такі обмеження називають інваріантами: вони мають залишатися істинними протягом роботи об'єкта. Якщо значення не відповідає правилу, конструктор може викинути виняток і не допустити успішного створення некоректного екземпляра.

```php
<?php
declare(strict_types=1);

class Course
{
    private string $title;

    public function __construct(string $title)
    {
        $title = trim($title);
        if ($title === '') {
            throw new InvalidArgumentException('Назва порожня');
        }
        $this->title = $title;
    }

    public function title(): string
    {
        return $this->title;
    }
}

$course = new Course(' PHP ');
echo $course->title();
```

Приклад для PHP 8.1+ нормалізує пробіли на краях і перевіряє результат. Властивість приватна, тому зовнішній код не може довільно змінити її після перевірки. Якщо пізніше додати метод перейменування, він також має підтримувати правило непорожньої назви.

У PHP 8 доступне скорочене оголошення властивостей через параметри конструктора з модифікатором видимості. Такий запис зменшує повторення, але не скасовує перевірок предметної області. Для першого ознайомлення явне оголошення властивості й присвоєння краще показує послідовність дій. Вибір форми не повинен змінювати поведінку класу.

Коли клас-нащадок оголошує власний конструктор, батьківський автоматично не викликається; за потреби використовують `parent::__construct(...)`. Якщо власного конструктора немає, можна успадкувати доступний батьківський. Тому додавання конструктора до нащадка вимагає перевірки, чи зберігається ініціалізація батьківського стану.

Залежності також передають через конструктор. Наприклад, сервіс каталогу може отримувати об'єкт сховища, замість самостійного читання пароля та створення з'єднання з MariaDB. Це робить вимоги сервісу видимими й полегшує перевірку з тестовим сховищем. Контейнер Laravel може автоматизувати створення залежностей, але їхній контракт визначає розробник.

Конструктор бажано залишати передбачуваним: не виводити HTML, не надсилати листи й не виконувати неочікуваних змін бази. Деструктор `__destruct()` має інше призначення та не є надійною заміною явного підтвердження операції чи транзакції.

## Завдання

1. Перевірте створення курсу з правильною назвою, пробілами на краях і самими пробілами.
2. Додайте перевірюваний метод перейменування, зберігаючи інваріант.
3. Поясніть, коли потрібний виклик батьківського конструктора і навіщо передавати сховище як залежність.
