# Метод PUSH та DELETE

## Мета

Розрізняти методи HTTP, їхні властивості та механізм server push; пояснювати безпечне проєктування видалення ресурсу. Самостійна робота — 2 год.

## Уточнення назви

Назву з README збережено. `PUSH` не є зареєстрованим методом HTTP у реєстрі IANA. `PUT` — метод створення або заміни стану ресурсу, `PATCH` — застосування часткових змін, а HTTP/2 server push — окремий механізм передавання відповідей. ## Теоретичний матеріал

HTTP-метод задає зміст дії над ресурсом, визначеним URI. Самої назви адреси недостатньо: `GET /courses/7` отримує подання курсу, а `DELETE /courses/7` просить видалити зв'язок ресурсу з цією адресою. Сервер перевіряє маршрут, особу користувача та його право виконувати дію. Наявність кнопки в інтерфейсі не замінює серверну авторизацію.

Метод `PUT` передає бажаний стан ресурсу за відомою адресою. Повторення однакового запиту має той самий передбачений ефект, що й одноразове виконання: це властивість ідемпотентності. `PATCH` описує зміни у форматі, який підтримує сервер; довільний JSON сам по собі не визначає універсальних правил оновлення. Ідемпотентність PATCH залежить від конкретної операції.

`DELETE` також ідемпотентний за семантикою HTTP. Після успішного видалення повторний запит не повинен створювати новий ресурс чи повторювати сторонню дію на зразок списання коштів. Водночас відповіді можуть відрізнятися: перше звернення повертає `204 No Content`, наступне — `404 Not Found`. Ідемпотентність стосується ефекту, а не тотожності статусів.

Видалення на рівні HTTP не обов'язково означає фізичне стирання рядка з MariaDB. Застосунок може позначити запис як видалений або прибрати його публічну доступність. Правила зберігання пов'язаних даних визначаються предметною областю. Тому перед реалізацією потрібно встановити, що саме перестає існувати для клієнта та як обробляються зв'язки.

HTML-форма не надсилає DELETE безпосередньо стандартним атрибутом `method`. У Laravel 10 застосовують POST-форму з прихованим полем підміни методу. Цей фрагмент призначений для Blade-шаблону навчального застосунку:

```blade
<form method="POST" action="/courses/7">
    @csrf
    @method('DELETE')
    <button type="submit">Видалити курс</button>
</form>
```

Маршрут DELETE та перевірку повноважень реалізують окремо. CSRF-токен захищає сеансову взаємодію від підробленого запиту, але не надає права видаляти чужий курс. Виконувати видалення через GET не слід: безпечний метод не повинен призначатися для зміни стану.

HTTP/2 server push дозволяє серверу ініціювати передавання відповіді на очікуваний запит через механізми протоколу. Це не команда PUSH, не оновлення запису бази та не заміна DELETE. Підтримку цього механізму конкретними клієнтами слід перевіряти окремо.

## Завдання

1. Порівняйте PUT, PATCH і DELETE за призначенням та ідемпотентністю.
2. Опишіть два послідовні DELETE одного курсу: стан до і після, можливі статуси.
3. Поясніть роль `@csrf`, `@method` та серверної авторизації у наведеній формі.
