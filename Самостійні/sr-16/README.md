# Шаблонізатор TWIG

## Мета

Пояснювати синтаксис Twig, організацію шаблонів та правила безпечного виведення; порівнювати його з Blade. Самостійна робота — 2 год.

## Теоретичний матеріал

Twig — окремий шаблонізатор для PHP, який перетворює шаблон і переданий контекст даних на текст, часто HTML. Він не є штатним шаблонізатором Laravel: у навчальному Laravel-проєкті використовується Blade. Знайомство з Twig дає змогу порівняти підходи до відділення серверної логіки від представлення.

У Twig `{{ ... }}` виводить вираз, `{% ... %}` позначає керувальні конструкції, а `{# ... #}` — коментар шаблону. Змінні записують без `$`. Фільтр після вертикальної риски перетворює значення, наприклад `title|upper`. Шаблон отримує тільки той контекст, який передав PHP-код; він не повинен самостійно діставати параметри з довільних джерел.

Наведений файл `courses.html.twig` демонструє список і повідомлення для порожнього набору. Очікуваний контекст — масив `courses`, елементи якого мають поле `title`.

```twig
<h1>Каталог курсів</h1>
<ul>
{% for course in courses %}
    <li>{{ course.title|escape('html') }}</li>
{% else %}
    <li>Курсів поки немає</li>
{% endfor %}
</ul>
```

Гілка `else` тут належить циклу й виконується, якщо елементів немає. Оператор крапки надає доступ до елементів або властивостей за правилами Twig; його поведінка не тотожна PHP-оператору `->`. Контракт контексту має визначати, чи кожен курс містить назву і що робити з відсутніми полями.

У PHP інтеграція включає завантажувач шаблонів, об'єкт `Environment` та виклик `render()` з іменем файла й даними. Файловий завантажувач обмежують відомим каталогом. Не слід передавати довільне ім'я файла з URL без перевірки або сприймати введення користувача як текст шаблону: це інший рівень довіри, ніж звичайні значення контексту.

Автоматичне екранування задається налаштуваннями середовища; для HTML його потрібно зберігати ввімкненим. У прикладі фільтр вказано явно, щоб показати контекст. `raw` позначає дані як безпечні й може вимкнути потрібний захист. Його не застосовують до неперевірених назв, коментарів або інших полів форми. Для URL і JavaScript потрібні відповідні правила, а не універсальне HTML-екранування.

Спільний каркас сторінки створюють через `extends` і блоки `block`. Дочірній шаблон заповнює потрібні області без копіювання всього HTML. `include` додає окремий фрагмент, наприклад картку курсу. Макроси допомагають повторно використовувати шаблонні конструкції, але складні обчислення та звернення до MariaDB залишають у PHP-компонентах.

Кеш скомпільованих шаблонів скорочує повторний розбір, але не є автоматичним кешем результату запиту до бази. У режимі розробки корисно виявляти відсутні змінні, щоб помилки контексту не виглядали як випадково порожній інтерфейс. Тести подання мають включати порожні дані та спеціальні символи.

## Завдання

1. Підготуйте контекст для трьох курсів і передбачте HTML-результат.
2. Перевірте логіку порожнього списку та назви `PHP <основи>`.
3. Порівняйте Twig і Blade: змінні, цикл, успадкування, екранування.

## Вимоги до результату

Подайте шаблон, приклад контексту та порівняння. Якщо Twig не встановлено, позначте результати як очікувані. Поясніть, чому дані користувача не можна вважати довіреним шаблоном.
