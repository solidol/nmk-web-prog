# Інкапсуляція та поліморфізм

## Мета

Пояснювати захист стану об'єкта та заміну реалізацій через спільний контракт, застосовувати ці принципи до компонентів вебзастосунку. Самостійна робота — 2 год.

## Теоретичний матеріал

Інкапсуляція об'єднує дані й операції над ними та визначає доступний зовнішній інтерфейс. У PHP `public` відкриває доступ ззовні, `protected` — у класі та нащадках, `private` — у класі, який оголосив член. Мета полягає у збереженні правил роботи об'єкта, а не лише в приховуванні назв властивостей.

Наприклад, тривалість курсу не повинна ставати від'ємною. Публічна властивість дозволяє записати неправильне значення будь-де. Приватна властивість і метод зміни з перевіркою зосереджують правило в одному місці. Набір механічних методів читання та запису без перевірок сам по собі ще не забезпечує змістовної інкапсуляції.

Поліморфізм дозволяє звертатися до різних об'єктів через спільний контракт. Код, який очікує назву курсу, може не знати, чи вона взята з пам'яті, конфігурації або сховища. Важливо, щоб реалізації дотримувалися погодженої поведінки, а не лише мали метод з однаковою назвою.

```php
<?php
interface CourseLabel
{
    public function text(): string;
}

class ShortLabel implements CourseLabel
{
    public function text(): string { return 'PHP'; }
}

class DetailedLabel implements CourseLabel
{
    public function text(): string { return 'Основи PHP'; }
}

function showLabel(CourseLabel $label): void
{
    echo htmlspecialchars($label->text(), ENT_QUOTES, 'UTF-8');
}

showLabel(new ShortLabel());
echo PHP_EOL;
showLabel(new DetailedLabel());
```

Функція `showLabel()` залежить від інтерфейсу, тому не потребує умов за назвами конкретних класів. Реалізацію методу обирає фактичний об'єкт. Текст екранується на межі HTML-виведення, а метод `text()` повертає звичайний рядок. Це дозволяє використовувати ту саму назву в іншому контексті, наприклад у JSON-відповіді.

Спадкування може підтримувати поліморфізм, але не є єдиним способом його досягнення. Незалежні класи можуть реалізувати один інтерфейс. Для сховища курсів це дозволяє мати реалізацію на MariaDB та тестову реалізацію в пам'яті. Контролер отримує залежність через конструктор і працює з контрактом, не створюючи конкретне сховище всередині кожного методу.

Контракт має описувати також відсутність результату й помилки. Якщо одна реалізація повертає порожній список, а інша за тієї самої умови завершує програму, вони не є взаємозамінними для клієнта. Узгоджують типи результатів, винятки та побічні ефекти. Однаковий синтаксис виклику не гарантує однакових очікувань.

Видимість властивостей не замінює авторизацію вебзапиту. `private` обмежує доступ із PHP-коду, але не визначає, хто має право редагувати курс. Перевірки користувача, CSRF-захист і валідація введення залишаються окремими обов'язками застосунку. Так само об'єктна обгортка SQL не усуває потреби параметризованих запитів.

## Завдання

1. Додайте третю реалізацію `CourseLabel`, не змінюючи `showLabel()`.
2. Спроєктуйте клас курсу з приватною тривалістю та методом її перевірюваної зміни.
3. Опишіть контракт сховища: що повертати для порожнього каталогу та як повідомляти про недоступну базу.

## Вимоги до результату

Подайте код і результати виклику трьох реалізацій. Поясніть, яке правило захищає інкапсуляція та який фрагмент демонструє поліморфізм. Наведіть приклад порушення контракту.
