# Лекція 5. HTTP-запити та методи POST, GET й інші

[Перелік лекцій](../README.md)

## Будова HTTP-повідомлення

HTTP — протокол обміну повідомленнями між клієнтом і сервером. Клієнт надсилає запит, сервер повертає відповідь. Метод запиту визначає бажану дію щодо ресурсу. Запит у HTTP/1.1 містить початковий рядок із методом та адресою ресурсу, заголовки й необов'язкове тіло. Відповідь містить код стану, заголовки та, за потреби, тіло. Порожній рядок відділяє заголовки від тіла.

```http
POST /orders HTTP/1.1
Host: example.com
Content-Type: application/json

{"productId": 7, "quantity": 2}
```

```http
HTTP/1.1 201 Created
Location: /orders/42
Content-Type: application/json

{"id": 42, "productId": 7, "quantity": 2}
```

У HTTP/2 і HTTP/3 спосіб передавання повідомлень інший, але значення методів і кодів стану зберігається.

## Метод POST

`POST` передає дані серверу для обробки за правилами цільового ресурсу. Типові приклади: створення замовлення, надсилання форми, завантаження файлу. Дані зазвичай містяться в тілі запиту; `Content-Type` указує їхній формат. При створенні ресурсу сервер може повернути `201 Created` і його адресу в `Location`. Інші успішні результати можуть мати коди `200 OK` або `204 No Content`.

Повторення однакового `POST` може створити два замовлення, тому метод загалом **не є ідемпотентним**. `POST` сам по собі не шифрує дані: для захисту їх передавання потрібен HTTPS.

HTML-форма з `method="post"` передає значення полів у тілі запиту. Формат визначає `enctype`:

- `application/x-www-form-urlencoded` — типовий формат; поля кодуються як пари «ім'я=значення»;
- `multipart/form-data` — кожне поле чи файл передається окремою частиною; використовують, зокрема, для завантаження файлів;
- `text/plain` — простий текстовий формат, рідкісний у практичній обробці форм.

Це **типи вмісту**, а не HTTP-методи. Поза HTML-формами тіло `POST` може бути й у форматі JSON.

## Метод GET

`GET` запитує представлення ресурсу. Його застосовують для читання сторінок, списків і результатів пошуку. Параметри вибору результату часто передають у URL після `?`:

```http
GET /products?category=books&page=2 HTTP/1.1
Host: example.com
Accept: application/json
```

Успішна відповідь зазвичай має код `200 OK` і тіло з даними. Якщо ресурсу немає, можливий `404 Not Found`. `GET` — **безпечний** метод: клієнт не просить змінити стан сервера. Він також **ідемпотентний**: повторення однакового запиту має той самий задуманий ефект. Запис сервером журналу запитів цьому не суперечить.

URL може зберігатися в історії браузера, закладках і журналах сервера. Не передавайте в його параметрах паролі чи інші секрети. Тіло в запиті `GET` не має загальновизначеної семантики, тому для передавання даних слід використовувати URL або інший метод.

HTML-форма з `method="get"` додає поля до URL. Якщо `method` не вказано, типовим для форми є `GET`. Відповіді на `GET` можуть кешуватися за правилами HTTP.

## Інші методи

### PUT

`PUT` створює ресурс за відомою адресою або замінює його представлення вмістом запиту. Наприклад, `PUT /profiles/42` може передати повний опис профілю. Метод ідемпотентний: повторне передавання того самого представлення має той самий задуманий результат. Коди відповідей при цьому можуть відрізнятися.

### PATCH

`PATCH` передає інструкції для часткової зміни ресурсу. Наприклад, можна оновити лише адресу доставки. Формат інструкцій указують у `Content-Type`. Метод не обов'язково ідемпотентний: «збільшити лічильник на 1» при повторенні змінює результат, а «встановити значення 5» може бути ідемпотентною операцією.

### DELETE

`DELETE` просить видалити зв'язок цільової адреси з ресурсом. Метод ідемпотентний за задумом, хоча повторна відповідь може мати інший код, наприклад `404 Not Found` після першого `204 No Content`.

### HEAD

`HEAD` запитує відповідь як для `GET`, але без тіла. Він корисний для перевірки наявності ресурсу або отримання метаданих, зокрема `Content-Type` чи `Last-Modified`, без завантаження вмісту.

### OPTIONS

`OPTIONS` запитує відомості про можливості взаємодії з ресурсом або сервером. Відповідь може містити `Allow` із переліком підтримуваних методів. Браузери застосовують `OPTIONS` і для попередніх запитів CORS.

### TRACE і CONNECT

`TRACE` призначений для діагностики: сервер повертає отриманий запит. Багато серверів вимикають його з міркувань безпеки. `CONNECT` просить посередника встановити тунель до цільового сервера; типовий приклад — з'єднання через HTTP-проксі.

## Порівняння методів

| Метод | Типове призначення | Безпечний | Ідемпотентний |
| --- | --- | --- | --- |
| `POST` | Передати дані для обробки або створення ресурсу | Ні | Загалом ні |
| `GET` | Отримати ресурс | Так | Так |
| `PUT` | Створити або повністю замінити ресурс | Ні | Так |
| `PATCH` | Частково змінити ресурс | Ні | Залежить від операції |
| `DELETE` | Видалити ресурс | Ні | Так |
| `HEAD` | Отримати заголовки без тіла відповіді | Так | Так |
| `OPTIONS` | Дізнатися про можливості взаємодії | Так | Так |
| `TRACE` | Діагностувати запит | Так | Так |
| `CONNECT` | Установити тунель | Ні | Ні |

**Безпечний** метод не призначений для зміни стану за запитом клієнта. **Ідемпотентний** метод має однаковий задуманий вплив на сервер після одного й кількох однакових запитів; коди відповідей можуть різнитися. Кешування — окрема властивість, яка залежить від методу й правил кешу.

Звичайні HTML-форми використовують `GET` і `POST`. Інші методи можна надсилати через JavaScript `fetch()` або інший HTTP-клієнт. Сервер повинен реалізувати семантику методів і перевіряти права доступу.
